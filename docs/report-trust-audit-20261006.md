## C. 신뢰도 설계 원칙 (구현)

- C1 **가정값 게이트.** 토지 평당가·분양가가 "초기 기본값"(사용자 미입력)이면:
  - 표지 4번째 KPI 를 "토지비 포함 총사업비" 대신 "실거래 추정 토지가 563.9억(참고)" 또는 "사업성: 판정 보류(토지가 미입력)" 로.
  - 요약·사업성 섹션의 IRR/ROE 큰 숫자 카드 대신 **토지가 시나리오 표**: [초기값 / 공시지가 기준 / 실거래 추정 기준] × [총사업비 · 세후이익 · ROE · 손익분기 분양률]. 기존 계산 함수 재사용. 음수 이익이면 그대로 음수로.
  - 판정 문구는 "판정 보류" 한 번만.
  - 기본값 여부를 store/입력에서 알 수 있는지 확인. 없으면 `isDefault` 플래그를 추가.
- C2 **데이터 상태 배지** 공통 컴포넌트: `조회`(출처·기준일) / `입력` / `가정` / `확인 필요`. 핵심 수치표·입력조건표의 값 옆에 작게 표시. 이미 있는 `lib/report/dataStatus.ts` 를 확장해 재사용.
- C3 **단일 출처 원칙.** 같은 수치는 같은 포맷 함수(예: `fmtPy1`)로만 출력. 평 환산 반올림 규칙 하나.
- C4 **출력 전 자동 일관성 검사** `lib/report/consistency.ts`: 입력 → 경고 목록. 최소 규칙:
  1) 기본값 토지가인데 실거래 추정과 3배 이상 차이 → C1 게이트 발동
  2) sunlightApplied=false 인데 일조 문구/표 출력 시도 → 차단
  3) 도로접면 코드와 전면도로 가정 폭 모순 → 경고
  4) 지하 마지막 층 바닥면적 < 다른 지하층의 50% → A5 방식으로 재표기
  5) 대출 비율 라벨과 실제 비율 차이 > 1%p → 라벨 보정
  테스트 포함.

## D. 레이아웃 (공백) — 원인과 규칙

원인: `wrap={false}` 가 큰 덩어리(3D 그림 묶음, 층별표 전체, 토지이용계획 표, 일조 진단 표, 섹션 헤더+첫 블록 묶음 등)에 걸려 있어 남은 공간에 안 들어가면 통째로 다음 쪽으로 넘어가고 공백이 생김. `minPresenceAhead=170` 이 다음 덩어리 높이보다 작아 제목만 쪽 하단에 남음. 표지 내용이 1쪽을 넘쳐 2쪽에 "발행/검수 상태" 2줄만 남음.

표본에서 확인된 증상: 2쪽 거의 빈 쪽 / 4쪽 상단에 제목 없는 3D 정면 2장 / 5쪽 하단 "3. 건축 규모 검토" 제목만 / 6쪽 3D 작게+하단 공백, 7쪽으로 정면도 분리 / 7쪽 하단 1/4 공백 / 11쪽 하단 "7. 부동산 IT 전문 종합 분석" 제목만 / 10쪽 비용 분해 차트 막대가 너무 작음.

규칙:
- D1 표지는 정확히 1쪽. 발행·검수 상태를 표지 안 고정 영역에. 표지 높이 계산이 넘치면 미확인 목록을 최대 3줄+"외 n건"으로 축약.
- D2 `wrap={false}` 는 작은 단위만: KPI 한 줄, 표 1행, (그림+캡션) 1세트, 6행 이하 작은 표. 긴 표는 행 단위 분할 + **표 머리 행 `fixed` 반복**.
- D3 제목(h2/h3)은 바로 뒤 첫 행/첫 블록과 함께 이동(제목+첫 행을 작은 wrap=false 로 묶음). minPresenceAhead 는 제목 다음 실제 최소 덩어리 높이에 맞춤.
- D4 3D 그림: 사시도 1장 + 정면 2장 을 한 세트(고정 높이)로 3장에서 1회만. 다른 곳의 중복 3D 제거(표지 제외).
- D5 비용 분해 차트: 막대 높이·라벨 크기 키우고 금액·비율 라벨을 막대 옆에.
- D6 큰 장(章)은 새 쪽에서 시작하지 않는다(공백 원인). 대신 장 제목 앞에 남은 공간이 첫 블록보다 작을 때만 넘어가게.
